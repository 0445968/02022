## Proposed product/privacy decisions (approval required)
- Public voting is verified-email signed-in accounts only, one immutable single-choice response, no anonymous voting, no IP/device tracking, no free text. This is a nonrepresentative audience poll, not an election or scientific survey. Public results explicitly released by authorized staff after closure and only with >=5 current responses; individual results are private. Staff manage_results sees aggregates, never identity export. One authored language per poll; UI bilingual, content translations are separate polls (no automatic translation or shared vote totals). Public navigation remains unlinked pending approval; localized page URLs ready. UTC explicitly labeled on form, editorial Bogota display for public close.
- Rate limit is five successfully recorded votes/minute per verified account, not a complete Sybil/bot defense. Real Auth verification, signup rate limiting/CAPTCHA, abuse policy, real concurrency and load tests remain release gates. No voting by guest or anonymous account. Privacy retention proposal: delete individual votes on account deletion via FK cascade; publish counts based on retained votes, suppress below threshold, never reopen capped poll; staff editorial audit retention and vote retention/anonymization after closure need explicit approval and privacy notice. No raw export or automated cleanup.
- Poll copy is immutable after publish; close or retire, create new poll to correct it. No retroactive edits to votes. Current reviewer capability checked on publication. State/version change audits record editorial actor only, not voter identity; cap closure is system-derived version increment, not staff action. No automatic poll activation or seeded permission changes. Public DB gate must be enabled separately by trusted database operator after approved policy, app flags, migrations, actual hosted checks, privacy/abuse controls and user consent; no live writes performed. No public nav until release approval.

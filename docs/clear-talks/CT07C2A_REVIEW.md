## Implementation and decisions
- EN/ES /newsroom/reports dynamic noindex/no-referrer route using existing scoped report RPC/service and default-off CT_COMMENT_REPORTS_ENABLED + CT_COMMENT_MODERATION_ENABLED + V2/no dev bypass. Separate sidebar Reports entry, report-only access discovery uses comment.manage_reports (not moderation grant), global or current published assignment exact scope. Reuses request-local cached capability discovery with first 100 assignment rows, bounded 50/batch and 5 concurrent permission checks; eligible assignments beyond cap can be missed, and multiple mode checks can duplicate work. Exact SQL authorization remains authoritative. No new database privileges, schema or service key.
- Report status open/reviewed/dismissed/actioned/all, story filter via headline and clear, 20 rows/page, no global counts. Selected report ID in query allows deep link and detail outside current page/filter only if exact authorized and optional story matches. Detail is loaded server-side with fresh scoped API read, current comment body/public author/status, original reported revision vs current revision, warning when changed or unknown; never claims historical body snapshot. Reader-authored reason rendered as plain text, structured reporter/reviewer identity absent. Free-text reason can contain self-identification. Last 20 immutable decision records with reason, timestamp, by-me and linked action indicator. Existing typography/colors/components retained.
- Decision controls available only from current canResolve + open/reviewed status; review or dismiss, actioned only if exact eligible moderation event ID. Required 12–1000 char reason and explicit confirmation; command sends report+comment revision, target, reason, exact matching event only when actioned, unique UUID. Strict projection validation and returned status/revision check; confirmed success reloads page, 409/uncertain result blocks resubmission until explicit refresh, in-page navigation guarded during request. Report resolution does not mutate comment, no automatic hide/remove. Terminal states remain read-only. Staff with report grant but not comment queue/moderation grant can resolve reports independently without new comment permission.
- Comments header link to Reports only when eligible. Selected report can open exact Comment detail via /newsroom/comments?status=all&storyId=...&commentId=...&reportId=... only when separate current comment queue/moderation grant exists on that story and Comments entry allowed. Comments page fresh readCommentDetail, validate story match; current action availability remains existing CT07a projection, not report permission. Back to report link rechecks report grant and actual report detail matches exact comment/story; on access failure omit return link without blocking independent moderation. Returning re-fetches current report (link prefetch disabled); if browser cache stale, CAS rejects mutation. No direct report action controls in Comments. No global styling/fonts changed. Real browser/mobile/keyboard QA pending.
- Reader report submission UI/API not implemented yet. Existing direct own-report reader policies unchanged. CT07c.2b narrow reader own report create/status and public comment Report button; CT07d bulk and cache visibility. No new DB migration.

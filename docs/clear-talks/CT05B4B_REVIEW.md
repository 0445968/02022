## Decisions / implementation
- Unapplied CLI-generated migration `20261124174529_ct05b_private_upload_quota.sql` (#45452027666). Hosted read-only preflight: media-drafts bucket absent, 0 private objects, private catalog absent, 22 legacy media records; storage.objects has name/bucket_id/owner_id/metadata and storage.allow_only_operation(text) exists. Install as part of staged initial rollout before enabling any private uploads. Migration aborts if any private objects/catalog records already exist, requiring explicit reconciliation; no silent backfill or deletion.
- Conservative initial cap **25 immutable reserved paths per Auth account, 10 MiB bucket max per file, 250 MiB upper bound on retained objects per uploader**. This is reserved capacity, not measured bytes or a monthly reset. No automatic slot release after failed upload, orphan cleanup, rejection or promotion; even a lost response consumes a reservation. Private original retention remains intact. Quota values are initial design choices, not user-approved settings. CT11 should add owner-configurable allowances, retention and reviewed reconciliation/reclamation (ensure no active/inflight upload and no reused stale signed URL; do not delete files/metadata via SQL). Reclamation is a production readiness requirement, not an implemented feature. Aggregate account allowance doesn't cap project-wide billing or egress.
- Private RLS table newsroom_private.private_upload_reservations, PK auth_user_id+slot constrained 1..25, DB-generated immutable UUID and path, unique(storage_path), narrow INSERT columns and self SELECT RLS; no UPDATE/DELETE privileges, no new service key, no definer. Both invoker RPCs require actual current newsroom.access and media.upload, derive auth.uid. Reservation tries each numbered slot using ON CONFLICT DO NOTHING, so concurrent transactions cannot allocate slot 26. Auth account rather than membership prevents quota reset by role change. No app supplied path/actor; API validates returned exact path after fresh auth.getUser, reserves before standard JWT upload, 429 on exhausted, no-store quota projection in existing list.
- Restrictive Storage INSERT policy requires exact own reserved path, current standard object.upload operation. Existing CT02i ownership/permission checks still apply. Denies signed-upload URL minting, private copy/move/resumable/S3 creation through authenticated path; restrictive UPDATE forbids private overwrite/move. Existing 10 MiB bucket limit, MIME restriction, upload signature/digest and promotion source verification retained. Catalog requires reservation of matching owner/path/extension, plus actual owned object existing CT02i policy. No managed storage table triggers or direct SQL object changes; only RLS policies, read metadata. Unlinked orphan cleanup remains possible via Storage API; reservation remains. Signed-download preview unchanged.
- Public media INSERT/UPDATE restrictive policies require media.approve AND media.edit_all for authenticated legacy public bucket access; original media.upload/ownership/reviewer claim policies still apply. Prevents restricted uploaders bypassing private quota and modifying public files. No new public object, public media row or story mutation. Broad reviewers can use existing reviewed promotion route without consuming another private slot; actual Storage operation behavior and original publication flow require disposable service rehearsal. Old app V2/private-draft flags remain off; no new flag needed because quota migration must be installed BEFORE private draft flag rollout. Existing private upload POST now requires quota RPC; absent migration fails closed. Existing EN/ES quota display, disabled upload at exhaustion, refresh after failure, no UI redesign; existing panel remainder English pending CT11 localization.
- Verified docs Nov 16/23 2026: https://supabase.com/docs/guides/storage/schema/design, https://supabase.com/docs/guides/storage/security/access-control, https://supabase.com/docs/guides/storage/schema/helper-functions and https://github.com/supabase/storage/blob/master/src/http/routes/operations.ts. Storage docs recommend API for files, RLS policies for access; signed URL operations bypass policy after issuance. Standard upload-only policy chosen for new private path. Real operation mapping, ownership, signed URL issuance denial and standard upload/promotion must be tested in disposable Supabase, not just mock SQL. Vercel function body ingress may impose a lower limit than 10MiB; verify actual deployment upload path and select safe transport before release.

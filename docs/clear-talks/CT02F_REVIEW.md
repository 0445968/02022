## Implemented scope (not a live deployment)
- `supabase/migrations/20261124001339_ct02f_publisher_versions.sql`, generated by pinned Supabase CLI v3.2.0 in GitHub Actions run **45295371087**, then committed. The temporary CLI-only workflow was removed.
- The **actual live PostgreSQL function** `public.publish_story_revision(p_story_id uuid,p_user_id uuid)` was read via `pg_get_functiondef` and preserved as `tests/fixtures/ct02f-original-publisher.sql`. Its transactional body after the original lock-statement marker is **identical** to the original; the replacement changes only the old legacy `profiles.is_editor` authorization block. An automated source comparison asserts preservation of prior-version INSERT, story UPDATE including `published_at` and `short_title`, category replacement, tag replacement and final revision DELETE.
- Original `SECURITY DEFINER SET search_path = ''` is deliberately retained to avoid disrupting the atomic publisher's existing privilege requirements. The rewritten gate first requires `auth.uid() = p_user_id` from the actual JWT, and then **current** `story.edit_all` OR `story.edit_assigned` **plus both** `story.publish` and `revision.publish` via the CT-02e database capability helper. Expired/suspended/revoked members and applicable explicit denies fail closed; `user_metadata` and legacy profile flags do not grant publishing. The function explicitly revokes EXECUTE from PUBLIC/anon and retains authenticated EXECUTE for working editorial compatibility, with its own access check.
- The Supabase Advisor **authenticated-callable SECURITY DEFINER** warning is **NOT fixed** merely by this hardening. The supported authenticated publishing RPC remains intentionally privileged; further review/alternative invoker design is still an approval condition. Do not claim the warning disappeared.
- `public.story_versions`: removes three verified live legacy author/editor RLS policies and adds scoped, deny-first authenticated SELECT/INSERT. Public/anonymous users cannot list unpublished historical versions. Direct authenticated history insertion requires the verified account as `created_by`, a current edit capability and an **exact** snapshot of the current story (headline, short title, subheadline, summary, body, author/editor IDs, language, primary category). No version UPDATE/DELETE grants or policies are added.
- `lib/services/stories.ts`: `restoreStoryVersion` now returns an error if the update fails or changes zero accessible stories, then snapshots the **confirmed post-restore row** with the complete author/editor/byline and short-title fields. This keeps existing restoration flows compatible with the stricter snapshot guard. Other historical data, public pages, media and fonts are not modified.

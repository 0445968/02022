## Implementation
- EN/ES /newsroom/comments server-rendered dynamic noindex/no-referrer page, feature gate CT_COMMENT_MODERATION_ENABLED requires V2/no dev bypass. Fresh verified session and navigation gate before queue read. Strict status/story UUID/search length/page validation, generic unavailable error and scoped API. Existing CT07a SQL remains sole mutation/data authority, no service key, role grant or new schema.
- Request-local cached canEnterCommentModeration checks global newsroom.access and comment.view_queue OR comment.moderate. Global moderators see empty queue; assigned-only moderator discovery reads own current membership/active assignment rows, then actual currently published due stories and exact per-story permission checks, not assignment alone. Bounded first 100 assignment rows, batches of 50 rows and 5 concurrent permission lookups; an eligible assignment beyond bound can be missed. Future scalable DB eligibility helper/keyset and performance/browser rehearsal recommended; no unrestricted scan or role-name defaults. Global navigation grant may still be denied on individual story; DB exact scope checks always authoritative. Report-only staff without queue/moderate grant do not get this entry; CT07c report-specific access route. Sidebar uses existing comments dictionary/icon, disabled legacy link removed, preserves existing team/review nav.
- CommentsWorkspace status filters pending/reported/published/hidden/deleted/all, literal search by public display name/body/headline, story filter by clicking displayed headline and clear filters, bounded 20/page with previous/next, no unscoped counts. Search is encoded in URL; staff should avoid entering sensitive personal data into filters (query can remain in browser/server access logs). Status tabs reset page; current filter preserved in pagination. Reported only returns rows with exact report permission in DB; no report disposition or reader identities exposed. No global open report badge.
- Detail pane GET no-store current authorized comment and last 20 immutable moderation events. Abort stale reads, no raw HTML, plain text/body and reason. State action helper mirrors pending approve/hide/remove, published hide/remove, hidden restore/remove, deleted/denied none. Required 12–1000 character reason and explicit confirmation for all; Remove warning states irreversible text loss, Hide preserves content, Restore returns pending. POST sends only actual comment ID, revision CAS, action, reason, unique command UUID. Conflict/uncertain blocks retries until fresh detail; success refreshes queue and detail, in-page navigation disabled while POST in flight. Browser-level navigation cannot be prevented in every circumstance; DB command uniqueness and CAS remain authority. No inline report disposition, bulk actions, real browser QA or visual screenshots yet. Existing fonts/global style unchanged.

## Implemented but NOT applied to production
- **Unapplied migration `supabase/migrations/20261124034804_ct03c_role_grant_editor.sql`**. Filename generated by pinned Supabase CLI v3.2.0 via GitHub Actions [#45321966824](https://github.com/0445968/02022/actions/runs/45321966824); temporary naming workflow removed. Requires CT-02b staff tables, CT-02c owner/Audit functions, backups and reviewed release sequence. Adds `grant_revision` to each built-in preset with default 0, **not** a single capability, role assignment, member, owner or invitation. Existing owner role template remains immutable in editor.
- `public.staff_preset_grant_allowed(role,capability,scope)` defines **role-specific maximum permitted capability-and-scope pairs**: managing/editor can receive reviewed editorial powers; freelancers/writers/copy editors only approved, principally assigned/own permissions; moderator and audience roles only respective vertical functions; media editor only reviewed media and assigned story abilities. Forbid `team.*`, `settings.security_admin`, `reader.personal`, `byline.manage` and all Owner template editing. Scope is constrained by each capability's reviewed ceiling; users may toggle inclusion but cannot choose broader scope. Raising a ceiling needs separate explicit review/migration.
- `staff_guard_preset_grant` BEFORE trigger enforces these ceilings and immutable grant identity even on direct service-role DML, and `staff_guard_preset_revision` blocks direct rekey/rename and makes revision strictly increment-by-one. CT-02c existing AFTER triggers transactionally log all role-grant INSERT/UPDATE/DELETE and preset-revision updates with the current owner actor, request UUID and 12–500 character reason.
- `public.staff_save_preset_grants(uuid,text,int,jsonb,text,uuid)` uses **SECURITY INVOKER**, service_role-only EXECUTE (PUBLIC/anon/authenticated revoked). It independently rechecks active, nonexpiring **employee Owner**, locks via the existing staff change advisory lock and target preset row, rejects Owner or unknown presets, unknown/duplicate/extra-field capability payloads and ceiling violations, and performs one atomic full-grant-set replacement. A version mismatch raises SQLSTATE `40001`, so stale tabs cannot silently overwrite another admin. A no-op set is rejected; a real change increments the preset revision exactly once and is fully auditable. There is NO bulk proposal seeding.
- `lib/permissions/staff-preset-input.ts` validates built-in role, revision, scoped grants, duplicate prevention, nonadministrative proposal ceiling, explicit confirmation, meaningful reason. It never trusts browser actor identity. `lib/services/staff-preset-admin.ts` requires current cookie-bound `auth.getUser`, `team.manage_roles` through live staff access and **all three** opt-in flags: `CT_STAFF_ACCESS_V2_ENABLED`, `CT_STAFF_ADMIN_MUTATIONS_ENABLED`, **new `CT_STAFF_PRESET_MUTATIONS_ENABLED`**, all **false**. Server-only service-role invokes the independently guarded DB RPC. `POST /api/newsroom/team/preset-change` same-origin only, JSON max 8192 declared bytes, typed input, conflict 409. Service key never sent to browser.
- Newsroom `RolePresetMatrixEditor.tsx` (bilingual, existing typefaces/Tailwind design) lets an authorized Owner review current configured roles versus proposed grant ceiling, toggle inclusion, see additions/removals and current revision, enter reason and explicit confirmation before an audited save; stale-revision warning requires reload. Owner role stays immutable/read-only. `StaffTeamManager.tsx` adds the editor in the existing role permissions section without altering global fonts, CSS, sidebar or public UI. All other viewers see noneditable version.
- `lib/services/staff-team-directory.ts` and `staff-team-types.ts` now include actual DB `grant_revision` and `presetMutationsEnabled`, derived only from current verified staff access + server flags. No role preset proposal inferred from profile/editor flags. `.env.example` adds `CT_STAFF_PRESET_MUTATIONS_ENABLED=false`.

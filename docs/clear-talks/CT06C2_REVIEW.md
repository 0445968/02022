## Implementation and decisions
- CLI-generated unapplied migration `20261124193511_ct06c_reviewed_schedule.sql` (#45471736789). Existing scheduled story preserved; **not** automatically approved, converted, published or queued. Before release review it manually, return to draft with explicit authorized action, request fresh independent review and schedule or publish through new workflow. No hosted writes or job registration.
- Private RLS reviewed_publication_schedules with no API table grants, one active pending/blocked row per story, exact approved request ID/kind/fingerprint and authorizing verified staff UUID, UTC due time, creation/termination/cancellation actors, safe failure SQLSTATE. One future queue within 1 year; change time by explicit cancel+create, retain prior record. New schedule queue intentionally does NOT set stories.status='scheduled' or revision.status='scheduled' or edit scheduled_at: doing so would mutate exact full-row/epoch approval; approved copy remains in_review while queue is separate. UI calls it Queued; CT08 calendar/list/dashboard must project schedule separately (effective scheduled status) rather than falsely infer from stored story status. Existing legacy direct scheduled status remains blocked. Master stored-status model deviation recorded for user review. Pending/blocked queue prevents immediate publication until cancelled. If source becomes unavailable (discard/archive), queue can still be cancelled by scoped RPC with known ID/kind; CT08 calendar should expose accessible stale/blocked entries independently of source review page. No automatic stale-queue deletion. No schedule on public revision status, actual revision publication still uses separate reviewed working copy.
- Refactors previous mandatory approval validation into private invoker validator with explicit internal actor argument, actual verified identity, current scoped view/edit/publish and revision permissions, exact latest in_review snapshot/epoch/request and current independent reviewer, consumed approval denial, same final media checks. Immediate public wrapper derives auth.uid only. Schedule creation requires additional current story.schedule, exact approval and media check; shared staff advisory lock. Pending schedule leaves fingerprint unchanged. Cancel uses exact ID/story/kind and current scheduler + publisher permissions (another authorized manager may cancel), no content mutation. Read projection exact current reviewer/submitter or scheduler, only id/kind/due/state/current/canCancel; current means exact matching snapshot, not guarantee current reviewer/grants/media/scheduler provider. No actor IDs or raw error text.
- Owner-only private invoker run_due_reviewed_publications(p_limit default 5, max10), postgres current_user and session_user, no Auth JWT, no public/service role EXECUTE or caller supplied time/actor. Try shared advisory lock, ordered bounded due rows with FOR UPDATE SKIP LOCKED, DB clock no premature execution, original scheduler's current story.schedule/publisher/verified identity and reviewer and exact approved content/media rechecked. Private common publisher validates exact queued ID/kind/request/fingerprint/actor/time; private transaction permit bound story/backend/xid, owner-only no JWT branch; never set JWT/GUC to impersonate. Internal revision apply requires permit and uses prevalidated explicit actor, old public RPC still revoked. Same atomic version, publication event, live content and schedule completion; repeated run no duplicate. Each failure rolls back subtransaction and marks blocked with safe SQLSTATE, no blind retry; cancellation and fresh authorization after diagnosis (manual fallback cancel then publish approved copy). Retained blocked records and counts available to future admin monitoring. A statement timeout/cancel can roll back batch; operator/job monitoring and real concurrent connections rehearsal CT08. No guarantee of minute-level dispatch or scheduler uptime. No cron install in migration.

## Scope implemented (code and proposed migration, NOT hosted)
- Staged migration `supabase/migrations/20261124020117_ct02j_media_promotion.sql`, filename generated using **pinned Supabase CLI 3.2.0** in GitHub Actions `45309261926`; temporary filename-only workflow removed. Depends on CT-02b/c/e/f/g/h/i, reviewed role grants and reconciliation of the restored database.
- Adds to `public.media_private_drafts`: a finite review state (`pending`, `publishing`, `published`, `rejected`, `failed`), original-file SHA-256, immutable deterministic public path, review actor/time, license/credit/rights evidence, source-to-public `published_media_id`, attempt number, lease timestamp and private recovery error. Existing historic file links and all public `media_assets` rows untouched.
- The **SECURITY INVOKER** review trigger validates every direct authenticated state transition and immutable source fields; SELECT/UPDATE RLS requires fresh `media.approve` and `media.edit_all` grants. Cannot publish without a corresponding **approved** public media record with the exact destination, reviewer owner and rights status. Terminal published/rejected reviews cannot be reset through direct Data API calls. Rights `restricted`/unknown, embargo-in-force, expired license, unverified origin or missing license/credit evidence are not promotable.
- A single narrow `storage.objects` INSERT policy allows `media-drafts` → existing public `media` `approved/<draft UUID>.<extension>` copy by a reviewer with `media.approve`, `media.upload`, `media.edit_all`, and a matching active draft review claim. It does **not** modify the existing public `media` bucket or earlier imported ownerless files, grants no generic public path overwrite, and does not move or delete the source.
- `POST /api/media/drafts/[id]/approve`: uses **only the actual cookie-bound Supabase account**, requires `media.approve` + `media.edit_all` + `media.upload` + `media.view_all`, rejects DEV_AUTH_BYPASS and stays unavailable unless BOTH `CT_STAFF_ACCESS_V2_ENABLED=true` and `CT_MEDIA_PRIVATE_DRAFTS_ENABLED=true`. Requires explicit `confirmRights=true`, signed rights notes and license/credit where applicable. Checks full original SHA-256 and file size, atomically claims a draft, uses Supabase Storage cross-bucket `copy` (without `upsert`), verifies copied bytes by SHA-256/size, creates/recovers a standard **draft** public `media_assets` record and promotes it to `approved` under separate media-approval rights, then marks private review `published` with linked approved media ID. No service-role client or hidden uploader impersonation.
- Partial cross-system failure is recorded as **failed** with original private bytes left intact. A reviewer with the same account and unchanged rights can retry the identical deterministic public destination, compare exact SHA-256 and recover an already-verified public media record. A `publishing` lease older than 15 minutes can be reclaimed using a compare-and-swap condition on attempt count/time. Storage copy + SQL are **not one atomic transaction**: on crash there may temporarily be an approved-rights public object without a catalog row, requiring inspection/retry. Do not claim a fully transactional Storage release.
- `POST /api/media/drafts/[id]/reject`: only current reviewer may reject an unclaimed pending draft with a recorded explanation (minimum 8 characters); the original remains privately stored for audit. `GET /api/media/drafts` lists user-scoped private drafts via RLS without returning Storage paths, signed URLs or fingerprints; reviewers can see relevant rights notes.
- `app/api/media/drafts/route.ts` now calculates a SHA-256 of uploads and stores it for verified promotion. `components/editorial/media-library/PrivateDraftMediaPanel.tsx` is integrated into `app/newsroom/(shell)/media/page.tsx` **only when the two feature flags are enabled**, with private upload, signed preview, rights fields, approval/retry and rejection. The normal `MediaLibrary` remains unchanged while the flags are off; once private mode is enabled its existing Upload buttons scroll to the private panel and its legacy public upload drawer is disabled.
- No fonts, color palette, global CSS, article screens, published story/media/byline data or public Storage URLs were altered.
